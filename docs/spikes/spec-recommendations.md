# Recommendations before P1

SPEC.md remains unchanged. These recommendations require an explicit spec decision rather than a silent implementation change.

1. **Performance workload:** specify input token distribution, truncation/chunking, batch size, thread count and execution provider. 100k/30 min requires 55.56 items/s; §10's ≥60 is a slightly stricter target. Gapmap's 50–70 docs/s used MPS/fp16; it is not a CPU baseline. Small-sample throughput cannot certify 100k imports.
2. **Calibrate the verdict, not just arbitrary pairs:** 20th–50th neighbours can be true matches; paraphrases may drift. A pairwise isotonic P(same) is not automatically a calibrated P(exists) for a maximum over a collection. Require adjudicated negatives, held-out query-level calibration, corpus/filter size checks and explicit wording “not found in this collection.” Keep the manual evaluation and external verification gates.
3. **Bridge gating:** §1.1 makes midpoint density/novelty and hierarchy exclusion mandatory, but §5.3's formula has neither, and its exclusions only mention near-duplicate siblings. Specify a hard novelty/density gate, ancestor/descendant exclusion, and semantic relevance check before a bridge is ranked.
4. **Model identity and offline loading:** store repository revision, file SHA-256, tokenizer, prefix, pooling, normalization, maximum tokens, dimension and numeric precision together. Never query vectors from one embedding model with another. Keep downloads separate from inference so offline mode has no lazy Hub calls. Test ONNX output parity before reusing gapmap vectors; speed does not establish parity or retrieval quality.
5. **Clustering/layout contracts:** keep display coordinates separate from region decisions. Validate finite inputs, handle an all-noise result, preserve noise flags, and retain multi-run stability gates. A map-only UMAP fallback must not silently become a clustering backend. Candidate-specific limitations and measurements are in the corresponding spike notes.
6. **Cross-platform validation:** three-OS CI is committed, including ML compile jobs, but cannot be called green until actually run. P0 local execution covers arm64 macOS only. P1 should require native inference/index smoke fixtures on Windows/Linux before advertising supported runtime behavior.

7. **P0-specific dependency decisions:** recommend BGE-small as the provisional CPU default (71.95/s versus Nomic 26.69/s), subject to retrieval evaluation. Resolve ort's automatic provider policy explicitly; do not use unmodified fastembed options as a CPU guarantee. Resolve LanceDB 0.40.0's local-only feature-gating bug before engine integration. Do not select the tested HDBSCAN or UMAP crates as production defaults on the strength of runtime alone; the notes document selection/API/quality failures.
